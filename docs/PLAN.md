# План проекта «Две жизни» — своя версия

## Цель

Сайт, где роман К. Е. Антаровой «Две жизни» удобно читать с компьютера и телефона на **английском**,
затем на **польском** (архитектура готова к другим языкам). На сайте запоминается место, где читатель
остановился, и можно скачать аккуратные **PDF и EPUB**.

Английский делаем **на основе старого перевода**: изучаем, выравниваем по оригиналу, редактируем.
Заново переводим только часть IV. Польский переводим с русского. Связка работы: основная модель-редактор
(выбирается сравнением), общий глоссарий, два уровня ревью — внутреннее агентами и внешнее
(запускает владелец), человеческая вычитка.

Связанные документы:
[INVENTORY.md](INVENTORY.md) — что есть ·
[ARCHITECTURE.md](ARCHITECTURE.md) — как устроены тексты, сайт и сборки ·
[TRANSLATION-PROCESS.md](TRANSLATION-PROCESS.md) — как редактируем, переводим и ревьюим ·
[../translation/decisions.md](../translation/decisions.md) — принятые решения.

## Исходная точка (кратко, подробно в INVENTORY.md)

- Русский оригинал частей **I, II, III** есть целиком (80 глав, ≈657 тыс. слов) в хорошем epub.
- От **части IV** есть только глава 1. Остальной текст нужно получить.
- Старый английский перевод есть для частей I, II и III: в новом Vol3 от владельца **все 33 главы
  присутствуют, признаков крупных пропусков не обнаружено; полнота уточняется при выравнивании** (DEC-010).
  Британская орфография. Систематические ошибки: князь → *duke*, «И.» → *I.*
  и др. **Берём за основу** (DEC-003).
- Старый bookdown-проект перенесён в `legacy/`, исходники — в `sources/`.

## Как устроена работа

- Этапы идут по порядку. **Каждый этап стартует только по команде владельца** (DEC-008).
- **Пилотный трек** (DEC-011, DEC-019): этапы 1–6 проходятся на **`p1-c01` плюс отрывки для сравнения
  моделей**. Массовая подготовка корпуса (этап 1 на все главы) делается, когда удобно — хоть раньше пилота,
  если она простая, — но **пилот не ждёт её**. Обязательна она только перед этапом 7.
- 🔍 **Контрольная точка**: внутреннее ревью агентами → разбор → commit + push → пакет для внешнего
  ревью → владелец получает стартовый промпт → стоп (TRANSLATION-PROCESS §7).
- Полноценный сайт — после пилота. Для пилота хватает локального просмотра сравнения и пробной сборки
  главы в EPUB/PDF (DEC-017).

## Этапы

### Этап 0. Порядок в репозитории и документы ✅
Старое → `legacy/`, исходники → `sources/`. Документы → `docs/`. Решения → `translation/decisions.md`.
Точка входа для агентов → `AGENTS.md`.

### Этап 1. Тексты в рабочий формат — три отдельных шага (DEC-014) · `p1-c01` ✅
Ни один шаг этого этапа **не меняет смысл и формулировки** старого перевода.

**1а. Русский оригинал** → `content/ru/part-{1,2,3}/ch-NN.md`, `content/book.yml`.
epub → Markdown по главам, один абзац на строку, ID абзацев, названия глав, стихи (`::: verse`), предисловие,
сноски. Чистка артефактов fb2, сверка с PDF, хеши глав. Фрагмент части IV и приложения — отдельно.

**1б. Извлечение старого перевода без правок** → `translation/legacy-en/raw/part-N/ch-NN.md`.
- Источники: Vol1, Vol2 (идентичны в корне и в `New/`) и новый Vol3 из `New/`.
- Разрешена только техника: номера страниц, колонтитулы, склейка строк в абзацы, переносы и
  восстановление пробелов там, где их потерял способ извлечения.
- **Слитный текст в новом Vol3** (≈1%, только часть III, пилот не затрагивает, INVENTORY §3) —
  сначала диагностика, потом решение (DEC-020):
  1. Посмотреть проблемные страницы визуально (рендер страницы в картинку).
  2. Сравнить несколько способов извлечения на этих страницах (pypdf в разных режимах, pdfminer
     с настройками межсимвольных интервалов, poppler `pdftotext`, PyMuPDF).
  3. Если пробелы на странице видны, восстанавливать их **по координатам символов** (разрыв между
     глифами), а не угадывать.
  4. Для гл. 1–9 — сверка с чистым PDF 2022 года (содержание то же).
  5. Словарь — только вспомогательный способ для остатка, и каждое сомнительное место **сверяется
     со страницей**. Отчёта о правках без такой сверки недостаточно.
- Абзацы нумеруются по порядку в PDF (`L001`, `L002` …). Отчёт о каждом техническом исправлении.

**1в. Выравнивание по абзацам оригинала** → `translation/legacy-en/alignment/pX-cYY.yml` и импорт в
`content/en/…` (стадия `legacy-imported`), текст по-прежнему без правок.
- Границы абзацев не обязаны совпадать: поддерживаются связи 1:1, 1:N, N:1, N:M, «нет в переводе»,
  «лишнее в переводе» (правила ID — ARCHITECTURE §3).
- Метод: длины + опорные точки (имена, числа, реплики). Неуверенные места выравнивает LLM
  с пометкой `confidence`. Отчёт: доля 1:1, список сложных мест.
- Импорт — отдельным коммитом (`en: import legacy p1` …), чтобы вся дальнейшая редактура была видна
  как дифф.

**Готово для пилота, когда:** `p1-c01` и отрывки для сравнения моделей прошли 1а → 1б → 1в, каждый ID
оригинала покрыт, отчёты есть.
*Статус (2026-09-26):*
- `p1-c01` прошла 1а → 1б → 1в: RU 135 абзацев, сверка с PDF без расхождений; EN 124 абзаца, пословная
  сверка с pypdf без расхождений; выравнивание проверено вручную целиком (`reviewed: full`), 64 из 99 связей 1:1;
  импорт без изменений текста.
- Для отрывков сравнения моделей извлечены целиком (RU + старый EN, сверки без расхождений) и выровнены
  автоматически `p1-c12`, `p1-c20`, `p2-c01`, `p3-c01`; вручную проверены только окна отрывков с контекстом
  (DEC-019). Калибровочный набор собран: `translation/calibration/` (4 прозаических отрывка по 710–820 слов RU
  + песня Ананды).
- Отчёты — `translation/reports/`. **Этап 1 для пилотного трека завершён.**
**Готово для масштабирования (до этапа 7):** то же для всех 80 глав, сложные места перечислены.

### Этап 2. Анализ старого перевода 🔍 · черновик готов, внутреннее ревью пройдено, **ждёт внешнего ревью** (`translation/reviews/en/analysis-legacy/request.md`)
**Результат:** `translation/analysis/legacy-en-report.md`.
- Стиль: регистр, голос рассказчика (части I и III — от первого лица, часть II — от третьего), речь
  Учителей, диалоги, орфография, пунктуация, реалии.
- Качество по выборке из всех трёх частей (~40–60 абзацев разных жанров) по категориям
  TRANSLATION-PROCESS §7.4 → ошибки на 1 000 слов по типам. Выборке достаточно сырого извлечения этих
  мест; полное выравнивание корпуса не требуется.
- Систематические ошибки — автоматическим поиском по сырому тексту (сплошное извлечение Vol1–Vol3).
- Согласованность между частями (Vol1 2018 → Vol3): менялись ли стиль и термины.
- Терминология старого перевода — затравка для глоссария (`en_legacy`).
- Выводы: что сохраняем, что правим всегда, глубина редактуры, окончательный вариант английского (DEC-004).
- 🔍 Внутреннее ревью выводов, затем внешнее. Владелец утверждает выводы.

### Этап 3. Ядро глоссария и персонажей 🔍
**Результат:** `translation/glossary.yml`, `translation/characters.yml` — **только ядро**, а не весь роман (DEC-011).
- Сквозные `core`-термины (ключевые понятия учения, титулы, обращения, главные персонажи и их имена),
  а также все термины пилотной главы и отрывков для сравнения моделей (этап 5).
- Разные значения одного слова — отдельные записи-значения; утверждение EN и PL раздельно (DEC-015).
- Для каждого термина — вариант старого перевода (`en_legacy`) и наше предложение, если тот ошибочен.
- 🔍 Ревьюеры подтверждают каждый термин явно; `core` утверждает владелец.
- Дальше глоссарий растёт **поглавно**: термины главы предлагаются и подтверждаются в рамках её цикла.

### Этап 4. Инструменты пилота
**Результат:** всё, что нужно для полного цикла на одной главе.
- `translation/style/en.md` — по выводам этапа 2, с примерами «было → стало».
- `translation/prompts/` — редактура, перевод, внутреннее ревью (по проходам), внешнее ревью,
  повторная проверка исправлений.
- `tools/`: `check`, `glossary`, `packet` (пакет внешнего ревью, привязанный к коммиту), `status`.
- **`compare`** — локальная HTML-страница главы в три колонки: RU | старый EN | новый EN с подсветкой
  изменений. Открывается в браузере без сервера.
- **`book --chapter`** — пробная сборка одной главы в EPUB и PDF.
- **Готово, когда:** на одной главе проходит технический цикл без ручных костылей.

### Этап 5. Выбор основной модели-редактора (DEC-012)
**Результат:** выбранная модель и зафиксированный промпт.
- 4–5 характерных отрывков по 600–900 слов: повествование от первого лица (часть I), драматическая
  сцена, живой диалог от третьего лица (часть II, Лондон), поучение или письмо Учителя (часть III),
  стихи (песня Ананды, гл. 20 части I) — оцениваются отдельно.
- Кандидаты: Claude (первый внутренний круг — модель текущих сессий, DEC-018) и модели, которые владелец
  запускает сам (Grok и другие по его выбору). Все получают один промпт, стайлгайд и ядро глоссария.
- Слепое сравнение (варианты A/B/C…) по критериям: точность относительно RU, соблюдение глоссария,
  бережность к старому тексту (без лишних переписываний), качество английского.
- Учитываем практичность: модель, которую агент не может вызвать сам, потребует скрипта с API-ключом
  владельца (ключ вне репозитория) или ручной работы.
- Отрывки сохраняются как **калибровочный набор**: на нём проверяется любая будущая смена модели.

### Этап 6. Пилот: полный цикл на одной главе 🔍
**Результат:** одна глава (рекомендация — часть I, гл. 1, ≈4 500 слов), прошедшая весь процесс, и
откалиброванный процесс.
- Редактура → проверки → внутреннее ревью → разбор → внешнее ревью (владелец) → разбор → повторная
  проверка серьёзных замечаний → `compare` и пробные EPUB/PDF → чтение владельцем.
- **Внутреннее ревью на пилоте — все три прохода** (точность, терминология, язык). Меряем, сколько
  **подтверждённых** замечаний добавляет каждый, и по итогам фиксируем достаточную схему для обычных и
  сложных глав (DEC-021).
- Метрики: доля изменённых абзацев, подтверждённые ошибки на 1 000 слов (до и после), вклад каждого
  внутреннего прохода и сколько добавило внешнее ревью.
- Калибровка стайлгайда, промптов, коридора длин.
- **Готово, когда:** владелец говорит «вот так и работаем».

### Этап 7. Английский: масштабирование 🔍
- Если ещё не сделана — **массовая подготовка**: этап 1 (1а–1в) на весь корпус, отложенные вопросы
  извлечения части III.
- **Редактура** всех 80 глав: часть I → часть II → часть III. Поглавно или пачками, когда метрики
  стабильны (TRANSLATION-PROCESS §7.6).
- **Часть IV** — новый перевод после получения текста (D7), с мини-пилотом в голосе отредактированного
  текста.
- После каждой части: сводка метрик, перечитывание на согласованность, обновление стайлгайда.
- Публикация по частям: часть I целиком → `en-v0.1` (сайт + PDF + EPUB), дальше по частям.

### Этап 8. Сайт (DEC-009) — можно параллельно с этапом 7
Локально (`npm run dev`), сборка `dist/` на любой хостинг, Docker для своего сервера. Чтение с
телефона и компьютера, запоминание позиции, переключение языка на том же абзаце, поиск, «Сообщить
об ошибке», PWA. **Готово, когда:** запускается одной командой, один и тот же `dist/` работает на сервисе
и в Docker, позиция восстанавливается после перезапуска браузера.

### Этап 9. PDF и EPUB полностью
Шаблоны Typst (6×9″, A4) и EPUB 3 (Pandoc) на основе пробной сборки пилота, epubcheck, проверка на
читалках, файлы в `dist/downloads/`.

### Этап 10. Польский 🔍
Тот же цикл в режиме «перевод» с русского: `style/pl.md`, утверждение терминов PL, пилот на одной
главе, выбор или калибровка модели для польского, масштабирование. Носитель языка на вычитку.

### Этап 11. Запуск и развитие
Домен, аналитика без cookie, страница «О проекте» (с благодарностью авторам старого перевода),
синхронизация между устройствами, параллельный режим RU|перевод (если позволят права), закладки.

## Риски

| Риск | Серьёзность | Что делаем |
|---|---|---|
| **Авторские права на оригинал.** Антарова умерла в 1959 г., но роман впервые опубликован в 1993 г. По ГК РФ (ст. 1281 п. 2) для посмертно обнародованных произведений срок, насколько я понимаю, — 70 лет от обнародования (до 2060-х). В ЕС (Польша), вероятно, 70 лет после смерти → до 1 января 2030. Перевод — производное произведение. Часть IV и «обновлённые редакции» — отдельные издательские права | **высокая** | Это не юридическая консультация, нужен юрист (D1). Пока работаем и держим сайт закрытым. Варианты: договориться с правообладателем; некоммерческий проект с готовностью снять по требованию (риск владельца); публичный запуск в ЕС после 2030 |
| **Права на старый английский перевод** — он основа (DEC-003) | высокая | D12. На сайте — благодарность и указание происхождения |
| Качество старого перевода хуже ожиданий | средняя | Этап 2 до начала работ, метрика «доля изменённых абзацев» на пилоте |
| Ошибки выравнивания (несовпадающие границы абзацев) | средняя | Отдельный шаг 1в с отчётом и `confidence`, связи N:M, ручной разбор сложных мест |
| Дрейф терминологии и голоса на 900 тыс. слов | высокая | Глоссарий со значениями, персонажи, синопсис, автопроверки, одна основная модель, калибровочный набор |
| Внутреннее ревью «своих» пропускает ошибки | средняя | Внешнее ревью обязательно, внешний ревьюер — из другого семейства, чем редактор (DEC-013) |
| LLM сглаживает, пропускает или «улучшает» текст | средняя | Проверка длин, категории `omission`/`addition`, правило «не переписывать ради переписывания», дифф в `compare` |
| Узкое место — владелец (внешние ревью, `core`-термины) | средняя | Внутреннее ревью снимает основную массу замечаний, пачки глав при стабильных метриках |
| Разные редакции частей (особенно IV) | средняя | Источник и хеш каждой главы, пометка редакции в `book.yml` |
