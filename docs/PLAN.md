# План проекта «Две жизни» — своя версия

## Цель

Сайт, где роман К. Е. Антаровой «Две жизни» удобно читать с компьютера и телефона на **английском**,
затем на **польском** (архитектура готова к другим языкам). На сайте запоминается место, где читатель
остановился, и можно скачать аккуратные **PDF и EPUB**.

Английский делаем **на основе старого перевода**: внимательно изучаем его, редактируем и допереводим
недостающее. Польский переводим с русского. В обоих случаях работает связка: LLM, общий глоссарий,
внешние ревью (их запускает владелец) и человеческая вычитка.

Связанные документы:
[INVENTORY.md](INVENTORY.md) — что есть ·
[ARCHITECTURE.md](ARCHITECTURE.md) — как устроены тексты, сайт и сборки ·
[TRANSLATION-PROCESS.md](TRANSLATION-PROCESS.md) — как переводим и ревьюим ·
[../translation/decisions.md](../translation/decisions.md) — принятые решения.

## Исходная точка (кратко, подробно в INVENTORY.md)

- Русский оригинал частей **I, II, III** есть целиком (80 глав, ≈657 тыс. слов) в хорошем epub.
- От **части IV** есть только глава 1. Остальной текст нужно получить.
- Старый английский перевод: части I и II полностью, часть III — гл. 1–9 из 33. Британская орфография.
  Есть систематические ошибки (князь → *duke*, «И.» → *I.*). **Берём за основу** (DEC-003).
- Старый bookdown-проект перенесён в `legacy/`, исходники — в `sources/`.

## Как устроена работа

- Этапы идут по порядку. **Каждый этап стартует только по команде владельца** (DEC-008).
- 🔍 **Контрольная точка ревью**: агент коммитит, пушит, кладёт `request.md`, даёт владельцу стартовый
  промпт для внешних моделей и останавливается (TRANSLATION-PROCESS §7.1).
- Этапы 6–7 (сайт, PDF/EPUB) можно вести параллельно с этапом 8 (масштабирование).

## Этапы

### Этап 0. Порядок в репозитории и документы ✅
- Старое → `legacy/`, исходники → `sources/` (переименованы, контрольные суммы в INVENTORY).
- План, архитектура, процесс перевода, инвентаризация → `docs/`. Журнал решений →
  `translation/decisions.md`.
- `AGENTS.md` и `CLAUDE.md` — точка входа для агентов.

### Этап 1. Тексты в рабочий формат: русский оригинал + выравнивание старого перевода
**Результат:** `content/ru/part-{1,2,3}/ch-NN.md`, `content/book.yml` и **старый перевод, разложенный по
тем же ID абзацев**: `content/en/part-{1,2,3}/ch-NN.md`, стадия `legacy-imported`.

*1а. Русский оригинал*
- Скрипт `tools/extract-ru`: epub → Markdown по главам, один абзац на строку, ID абзацев, названия глав
  (в части I — в заголовке, в частях II–III — подзаголовок), эпиграф-стихотворение, предисловие
  «Об авторе», сноски. Чистка артефактов fb2.
- Автоматическая сверка с PDF. Фрагмент части IV и приложения — в `content/ru/part-4/` и
  `content/ru/appendix/`.
- Заморозка: хеши глав, стадия `source-ready`.

*1б. Старый английский перевод*
- Извлечь текст из PDF (самые свежие версии: Vol1 2018, Vol2 2021, Vol3 2022). Убрать номера страниц
  и колонтитулы, склеить строки в абзацы, починить переносы.
- Разбить по главам и **выровнять по абзацам с русским** (длины + опорные точки: имена, числа,
  реплики диалогов; спорные места выравнивает LLM). Абзацы, которые не удалось сопоставить, помечаются
  для ручного разбора.
- Импорт в `content/en/…` **без единой правки текста** — отдельным коммитом (`en: import legacy p1` …).
  Все последующие правки будут видны как дифф относительно старого перевода.
- **Готово, когда:** 80 глав RU извлечены; 56 глав EN (26 + 21 + 9) импортированы; все ID совпадают или
  расхождения перечислены в отчёте; начало гл. 10 части III учтено.

### Этап 2. Анализ старого перевода 🔍
**Результат:** `translation/analysis/legacy-en-report.md` и выводы для стайлгайда.
- **Стиль:** регистр, голос рассказчика, речь Учителей, диалоги, орфография (британская, оксфордская
  *-ize* — подтвердить), пунктуация, как переданы реалии и эзотерические понятия.
- **Качество по выборке:** по ~40–60 абзацев из разных частей (начало, середина, конец, беседы Учителей,
  бытовые сцены) сравнить с оригиналом по категориям TRANSLATION-PROCESS §7.2. Получится оценка
  ошибок на 1 000 слов по типам.
- **Систематические ошибки:** автоматический поиск по всему корпусу (*duke*/князь, *I.*/И., *Joan*/Жанна
  и т. п.), кальки и повторяющиеся конструкции.
- **Терминология старого перевода:** как переведены ключевые понятия и имена. Это прямая затравка
  для глоссария (поле `en_legacy`).
- **Согласованность между частями:** не менялся ли стиль и термины от части I (2018) к части III (2022).
- **Выводы и рекомендации:** что сохраняем, что правим всегда, глубина редактуры, окончательное решение
  по варианту английского (DEC-004).
- 🔍 Контрольная точка: отчёт плюс выборка `ID | RU | EN` → два внешних ревьюера проверяют выводы.
  Владелец утверждает выводы.

### Этап 3. Глоссарий v0 и персонажи 🔍
**Результат:** `translation/glossary.yml`, `translation/characters.yml` (схема — TRANSLATION-PROCESS §9).
- Кандидаты из русского текста: имена собственные, слова с заглавной буквы, частотные понятия
  и устойчивые формулы (скрипт: частотность, n-граммы).
- Для каждого — вариант из старого перевода (`en_legacy`) и, если он ошибочен, наше предложение.
- Разметка `core` / `secondary`, контекст первого появления.
- 🔍 Контрольная точка: внешние ревьюеры → `secondary` утверждаются по их вердиктам; ~50–100 `core`
  утверждает владелец.
- **Готово, когда:** все `core` из частей I–III утверждены. Дальше глоссарий только пополняется по
  правилам §9.

### Этап 4. Набор редактора и переводчика
**Результат:** всё, что агент читает перед заходом, и автоматические проверки.
- `translation/style/en.md` — на основе выводов этапа 2: что сохраняем из голоса старого перевода, что
  правим, примеры «было → стало».
- `translation/prompts/{revise,translate,review,fix}.md` — промпты для редактуры, перевода, внешнего
  ревью и разбора замечаний.
- `tools/`: `check`, `glossary`, `packet` (сборка `request.md`), `review:merge`, `status`.
- **Готово, когда:** на одной главе проходит полный технический цикл: запрос на ревью собирается,
  ответ в формате §7.2 разбирается, проверки работают.

### Этап 5. Пилот: часть I, главы 1–3 (редактура) 🔍
**Результат:** три главы, прошедшие весь процесс, и откалиброванный процесс.
- Редактура старого перевода по стайлгайду → проверки → запрос на ревью → **два** внешних ревьюера →
  разбор → чтение владельцем.
- Метрики: доля изменённых абзацев, замечания ревьюеров на 1 000 слов. Для сравнения ревьюеры
  оценивают и исходный старый вариант, чтобы увидеть прирост качества.
- Калибровка стайлгайда, промптов и коридора длин.
- **Готово, когда:** владелец говорит «вот так и редактируем».

### Этап 6. Сайт MVP
**Результат:** рабочий сайт на preview-адресе с пилотными главами.
- Astro: главная и выбор языка, оглавление, страница главы, навигация, настройки читателя
  (шрифт, тема), запоминание позиции (`localStorage`), «Продолжить чтение», переключение языка
  на тот же абзац, поиск (Pagefind), «Сообщить об ошибке», PWA.
- Деплой: Cloudflare Pages, preview на каждую ветку. Свой домен — когда владелец его выберет.
- Проверка на реальных телефонах (iOS Safari, Android Chrome), Lighthouse ≥ 95.
- **Готово, когда:** пилотные главы удобно читаются с телефона, позиция восстанавливается после
  закрытия вкладки и перезапуска браузера.

### Этап 7. PDF и EPUB
**Результат:** кнопки «Скачать PDF / EPUB» на сайте отдают красивые файлы.
- Шаблон Typst (6×9″ и A4), Literata, колонтитулы, оглавление с закладками, буквицы, титул с версией.
- EPUB 3 через Pandoc, свой CSS, обложка, epubcheck в CI.
- Проверка на читалках: Apple Books, Google Play Books, KOReader или PocketBook, Kindle.
- **Готово, когда:** файлы собираются в CI по тегу, проходят epubcheck, владелец одобрил вёрстку.

### Этап 8. Английский: масштабирование 🔍
**Результат:** весь английский текст.
1. **Редактура:** часть I (гл. 4–26) → часть II → часть III гл. 1–9. Контрольные точки — по главе или
   пачке глав (TRANSLATION-PROCESS §7.3).
2. **Новый перевод:** часть III гл. 10–33 — сначала мини-пилот в голосе отредактированного текста
   (§6.3), затем по главам. Если найдётся более полная версия старого перевода части III (D11),
   эти главы тоже идут в редактуру.
3. **Часть IV** — после получения текста (D7).
- После каждой части: сводка метрик, выборочное перечитывание на согласованность, обновление стайлгайда.
- Публикация по частям: часть I целиком → релиз `en-v0.1` (сайт + PDF + EPUB), дальше по частям.

### Этап 9. Польский 🔍
Тот же конвейер в режиме «перевод» с русского: `style/pl.md`, колонка `pl` в глоссарии и персонажах,
пилот (часть I, гл. 1–3), калибровка, масштабирование. Носитель польского на вычитку очень желателен.

### Этап 10. Запуск и развитие
Домен, аналитика без cookie, OG-картинки, страница «О проекте и переводе» (с благодарностью авторам
старого перевода), синхронизация прогресса между устройствами, параллельный режим RU|перевод
(если позволят права), закладки.

## Риски

| Риск | Серьёзность | Что делаем |
|---|---|---|
| **Авторские права на оригинал.** Антарова умерла в 1959 г., но роман впервые опубликован в 1993 г. По ГК РФ (ст. 1281 п. 2) для посмертно обнародованных произведений срок, насколько я понимаю, — 70 лет от обнародования (до 2060-х). В ЕС (Польша), вероятно, 70 лет после смерти → до 1 января 2030. Перевод — производное произведение. Часть IV и «обновлённые редакции» — отдельные издательские права | **высокая** | Это не юридическая консультация, нужен юрист (D1). Пока работаем и держим сайт закрытым. Варианты: договориться с правообладателем; некоммерческий проект с готовностью снять по требованию (риск владельца); публичный запуск в ЕС после 2030 |
| **Права на старый английский перевод** — теперь он основа (DEC-003) | **средняя → высокая** | D12: связаться с автором или командой. На сайте — благодарность и указание происхождения |
| Качество старого перевода хуже ожиданий (редактура превратится в переписывание) | средняя | Этап 2 даёт объективную оценку до начала работ. Метрика «доля изменённых абзацев» на пилоте |
| Дрейф терминологии и голоса на 900 тыс. слов | высокая | Глоссарий (вариант Б), персонажи, синопсис, автопроверки, контрольные точки, одна модель на язык |
| Шов между отредактированным и новым переводом (часть III, гл. 10) | средняя | Мини-пилот, стайлгайд, построенный на голосе старого перевода |
| LLM сглаживает, пропускает или «улучшает» текст | средняя | Проверка длин по абзацам, категории `omission`/`addition` в ревью, правило «не переписывать ради переписывания» |
| Узкое место — владелец (ревью вручную, утверждение `core`) | средняя | Вариант Б для глоссария, пачки глав на ревью, когда метрики стабильны |
| Разные редакции частей (особенно IV) | средняя | Источник и хеш каждой главы, пометка редакции в `book.yml` |
| Потеря позиции чтения (Safari чистит хранилище, смена устройства) | низкая | PWA, потом синхронизация по коду |

## Оценка объёма

| | Глав | Слов RU | Режим |
|---|---|---|---|
| Часть I | 26 | ≈171 тыс. | редактура |
| Часть II | 21 | ≈168 тыс. | редактура |
| Часть III, гл. 1–9 | 9 | ≈79 тыс. | редактура |
| Часть III, гл. 10–33 | 24 | ≈239 тыс. | новый перевод (или редактура, если D11) |
| Часть IV | ? | ? | новый перевод |

- Средняя глава ≈8 тыс. слов — один рабочий заход плюс один заход разбора замечаний.
- Узкое место — **внешние ревью и решения владельца**, а не сама редактура. Поэтому этапы 2–3 делаем
  основательно: хороший стайлгайд и глоссарий сокращают число замечаний дальше.
