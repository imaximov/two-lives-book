# Архитектура: тексты, сайт, PDF/EPUB

## 1. Принципы

1. **Один источник правды.** Тексты всех языков лежат в `content/` в простом текстовом формате.
   Сайт, PDF и EPUB собираются из них автоматически. Руками HTML/PDF никто не правит.
2. **Абзац — единица всего.** У каждого абзаца оригинала есть постоянный ID, и перевод обязан
   сохранять те же ID. На этом держатся проверки перевода, ревью, переключение языка «на том же месте»,
   параллельное чтение и запоминание позиции.
3. **Статичный сайт.** Сервер не нужен: сайт — набор файлов на CDN. Это быстро, бесплатно и почти
   не ломается. Динамику (синхронизацию между устройствами) добавим позже маленьким serverless-сервисом.
4. **Всё проверяется в CI.** Каждый push гоняет проверки текстов и сборку. На каждую ветку или PR
   получаем preview-адрес сайта для вычитки.

## 2. Структура репозитория (целевая)

```
AGENTS.md                  ← точка входа для любого агента (Claude, Codex, Gemini …)
CLAUDE.md                  ← ссылается на AGENTS.md
docs/                      ← план, архитектура, процесс перевода, инвентаризация
sources/
  ru/original/             ← исходные epub/pdf оригинала (только чтение, с контрольными суммами)
  en-legacy/               ← старый английский перевод (PDF, основа для редактуры EN)
content/
  book.yml                 ← структура книги: части, тома, главы, ID, названия на всех языках
  ru/part-1/ch-01.md       ← канонический оригинал (извлекается из epub скриптом, потом правится руками)
  en/part-1/ch-01.md       ← английский: сначала импорт старого перевода по ID абзацев, дальше наша редактура
  pl/part-1/ch-01.md       ← наш польский перевод
translation/               ← «кухня» перевода (подробно в TRANSLATION-PROCESS.md)
  glossary.yml             ← термины RU → EN/PL
  characters.yml           ← персонажи: имена, транслитерации, пол, обращения ты/вы
  style/en.md, style/pl.md ← стайлгайды по языкам
  synopsis/part-1.md       ← краткое содержание по главам (контекст для агентов)
  decisions.md             ← журнал принятых решений (DEC-001 …)
  analysis/                ← анализ старого перевода и другие отчёты
  prompts/                 ← промпты: редактура, перевод, ревью, разбор
  reviews/<lang>/<unit>/   ← request.md (запрос на ревью), ответы ревьюеров, resolution.md
  queries/<lang>/<ch>.md   ← открытые вопросы к владельцу проекта
  status.yml               ← стадия каждой главы на каждом языке
tools/                     ← скрипты (TypeScript/Node): извлечение, проверки, пакеты для ревью, сборка книг
site/                      ← сайт (Astro)
publishing/                ← шаблоны PDF (Typst) и EPUB (CSS, метаданные), обложки
legacy/                    ← старый bookdown-проект (история, не трогаем)
```

> Сайт (`site/`) — это только код. Тексты, которые переводят и вычитывают, лежат в `content/`,
> чтобы правки текста не смешивались с правками кода. Вычитывать удобнее всего на preview-сайте,
> а ошибку исправлять в соответствующем `content/<lang>/…/ch-NN.md`.

## 3. Формат текстов (`content/<lang>/part-N/ch-NN.md`)

Markdown с YAML-шапкой. **Один абзац — одна строка**, без жёстких переносов: так диффы
читаются нормально, а LLM не ломает структуру.

```markdown
---
id: p1-c01
lang: en
part: 1
volume: 1
chapter: 1
title: "At My Brother's"
source_hash: 3f9a…            # хеш русской главы, с которой делался перевод
status: draft                 # см. стадии в TRANSLATION-PROCESS.md
---

{#p1-c01-001} The events I now recall take me back to days long gone, to my distant youth.

{#p1-c01-002} “Who could they be?” I wondered, going back to where I had met them.

::: verse {#p1-c01-003}
I am but a wanderer on this earth.
Amid the toil, the passions and the pain…
:::
```

Правила:

- **ID абзаца** `{#p<часть>-c<глава>-<NNN>}` ставится в начале строки. Назначается один раз при извлечении
  оригинала и потом не меняется никогда. Если в оригинал добавили абзац, он получает ID с суффиксом
  (`…-012a`), а остальные ID не перенумеровываются.
- Перевод содержит **тот же набор ID в том же порядке**. Склеивать абзацы нельзя. Разбить один абзац
  на два можно только в крайнем случае, суффиксом `.2` (`{#p1-c01-012.2}`).
- Разметка минимальная: `*курсив*`, сноски `[^1]`, блоки `::: verse`, `::: epigraph`, `::: letter`
  (письма и записки в тексте), `::: note`.
- Типографика — по правилам языка (кавычки, тире, многоточие), см. стайлгайды.
- `content/book.yml` описывает структуру книги (части → тома → главы) и названия на всех языках.
  Из него строятся оглавления, навигация и сборка.

Парсер формата один (`tools/lib/book-format.ts`). Им пользуются проверки, сайт, PDF и EPUB.

## 4. Сайт

### Технологии

| Что | Выбор | Почему |
|---|---|---|
| Генератор | **Astro** (TypeScript) | Статическая генерация, нулевой JS по умолчанию (быстро на телефоне), встроенная i18n-маршрутизация, content collections. Интерактив «островками» только там, где нужно |
| Поиск | **Pagefind** | Статический полнотекстовый поиск по всем языкам, без сервера |
| Шрифт | **Literata** (OFL) | Создан для длинного чтения с экрана, кириллица и польская латиница, есть курсив. Тот же шрифт в PDF/EPUB |
| Хостинг | **Cloudflare Pages** (альтернатива — GitHub Pages) | Бесплатно, быстрый CDN, preview на каждую ветку или PR, свой домен, потом Workers/D1 для синхронизации |
| Офлайн | PWA (service worker) | Можно «установить» на телефон и читать без сети. Установленное приложение ещё и защищает прогресс от автоочистки хранилища в Safari |

### URL-схема

```
/                         → выбор языка (автоматически по браузеру, с запоминанием)
/en/                      → обложка, о книге, оглавление, «Продолжить чтение», скачать PDF/EPUB
/en/part-1/               → оглавление части
/en/part-1/ch-01/         → глава
/en/part-1/ch-01/#p1-c01-042 → конкретный абзац (ссылкой можно поделиться)
/pl/…                     → то же для польского
```

Переключатель языка ведёт на **тот же абзац** в другом языке: ID общие.

### Функции

**MVP (к первому запуску):**
- Удобное чтение с компьютера и телефона: адаптивная вёрстка, ширина строки 60–75 знаков, крупный кегль.
- Настройки читателя: размер шрифта, тема (светлая / сепия / тёмная, по умолчанию как в системе),
  межстрочный интервал. Хранятся в `localStorage`.
- **Запоминание места чтения** (подробно ниже) и кнопка «Продолжить чтение» на главной.
- Навигация: оглавление, «предыдущая / следующая глава», прогресс по главе, клавиши ← →.
- Переключение языка с сохранением позиции.
- Скачивание PDF и EPUB (по частям и целиком) со страницы книги.
- Поиск.
- Кнопка «Сообщить об ошибке» у абзаца: открывает заранее заполненное GitHub issue (или форму)
  с ID абзаца и языком.
- SEO и шаринг: `lang`, `hreflang`, sitemap, OpenGraph-картинки.

**Потом:**
- Параллельный режим «оригинал | перевод» на широком экране (для тех, кто учит язык).
  Нужен ли русский текст на сайте, зависит от решения по правам (PLAN.md, D1).
- Синхронизация прогресса между устройствами (ниже).
- Закладки и заметки.
- Аудио (TTS) — отдельный большой вопрос, не в этом плане.

### Запоминание места чтения

**Решение: `localStorage` в браузере, куки не нужны.**

Почему не куки: куки отправляются на сервер с каждым запросом, а сервера у нас нет — читать их некому.
Лимит ~4 КБ, и формально они сильнее тянут за собой cookie-баннер. `localStorage` работает только
в браузере, никуда не передаётся, хранит сколько нужно. Для функции, которую пользователь сам использует,
согласие, как правило, не требуется (не юридическая консультация, при запуске сверимся).

Что храним:

```jsonc
// localStorage["tl:progress:v1"]
{
  "en": { "chapter": "p1-c05", "para": "p1-c05-117", "offset": 0.35, "updatedAt": "2026-10-01T20:15:00Z" },
  "pl": { "chapter": "p1-c01", "para": "p1-c01-010", "offset": 0.0,  "updatedAt": "…" }
}
// localStorage["tl:settings:v1"] = { "fontSize": 19, "theme": "sepia", "lang": "en" }
// localStorage["tl:read:v1"]     = { "en": ["p1-c01","p1-c02", …] }   // прочитанные главы — галочки в оглавлении
```

Как работает:

1. `IntersectionObserver` следит, какой абзац сейчас вверху экрана. При смене абзаца позиция
   сохраняется с задержкой ~1 с, а также на `visibilitychange` и `pagehide` (важно для телефонов,
   где вкладку просто сворачивают).
2. На главной — большая кнопка «Продолжить: Часть I, глава 5 “В Севастополе”».
3. Если открыть главу без `#якоря`, а в ней есть сохранённая позиция, страница прокручивается к абзацу
   и показывает ненавязчивую плашку «Вы остановились здесь · В начало главы».
4. Позиция хранится по ID абзаца, а не в пикселях, поэтому смена шрифта, устройства или обновление текста
   позицию не ломают.
5. Всё обёрнуто в `try/catch`: в приватном режиме или при запрещённом хранилище сайт просто работает
   без запоминания.

Ограничение: позиция живёт в одном браузере на одном устройстве. Safari может очистить данные сайта,
который не открывали 7+ дней (установленное PWA от этого защищено).

**Синхронизация между устройствами (этап 2, по желанию):** без регистрации и паролей.
Пользователь нажимает «Синхронизировать» и получает код вида `KORA-7F3Q` (или QR). На другом устройстве
вводит код, и прогресс подтягивается. Реализация: Cloudflare Worker + D1/KV, хранится только
`{код → прогресс}`, без персональных данных. Вариант с входом по ссылке из email (magic link) можно
добавить позже, если будет спрос.

### Статусы глав на сайте

- Production (`main`) показывает главы со статусом `published`. Остальные главы видны в оглавлении
  как «скоро».
- Preview-сборки показывают **все** главы с плашкой стадии (`draft`, `reviewed`…). Здесь и идёт вычитка.

## 5. PDF и EPUB

| Формат | Инструмент | Детали |
|---|---|---|
| **PDF** | **Typst** | Современная замена LaTeX: быстрый, простой шаблон, отличная типографика, кириллица и диакритика без мучений. Формат 6×9″ (книжный) с полями под печать и A4 для печати дома. Оглавление с закладками, колонтитулы (часть / глава), висячая пунктуация, переносы по языку, буквица у начала главы. Отдельно по частям (I, II, III, IV) и полное издание |
| **EPUB 3** | **Pandoc** + свой CSS | Навигация по частям и главам, метаданные (`lang`, автор, переводчик, версия), встроенный шрифт, обложка. Проверка **epubcheck** в CI |

- Источник тот же: `tools/build-book` читает `content/` и генерирует `.typ` для Typst и HTML или
  Markdown для Pandoc.
- В каждом файле на титуле версия и дата (`EN v0.3 · 2026-11-02 · Part I`) и короткая ссылка на сайт.
- Обложка — типографская: название, автор, орнамент. Никаких картинок с неясными правами.
- Файлы собирает CI на каждый релиз и выкладывает на сайт (`/downloads/…`) и в GitHub Releases.

## 6. Инструменты (`tools/`)

Node 22 + TypeScript. Команды через `npm run` в корне:

| Команда | Что делает |
|---|---|
| `extract:ru` | epub → `content/ru/**` (структура, ID, чистка артефактов fb2) |
| `check` | все автоматические проверки текстов (структура ID, длины, глоссарий, имена, типографика, остатки кириллицы) |
| `glossary <chapter> <lang>` | выдаёт подмножество глоссария и персонажей, встречающихся в главе (контекст для агента) |
| `extract:en-legacy` | PDF старого перевода → абзацы → выравнивание с RU по ID → `content/en/**` (стадия `legacy-imported`) + отчёт о несопоставленных абзацах |
| `packet <chapter> <lang>` | собирает `translation/reviews/<lang>/<unit>/request.md` для внешнего ревью (инструкция + выровненный RU/перевод + новые термины + JSON-схема ответа) |
| `review:merge` | сводит JSON-ответы ревьюеров в единый список замечаний |
| `status` | сводка по `translation/status.yml`: что на какой стадии |
| `build:site`, `build:pdf`, `build:epub` | сборки |

## 7. CI (GitHub Actions)

- На каждый push и PR: `npm run check` (проверки текстов) → сборка сайта → preview-деплой.
- На тег `en-v*` / `pl-v*`: сборка PDF и EPUB → epubcheck → GitHub Release → обновление `/downloads`.
- Проверки текстов — **блокирующие** для структурных ошибок (ID, битая разметка) и **предупреждения**
  для остальных (длины, стилистика), чтобы не мешать работе над черновиками.
